## 4. 정한 것 (담임 결정, 바꾸지 말 것)

- 기간 4주(11/9~12/4), 쿠폰 **30칸 / 45칸**(포스터에 인쇄됨). 간식이 다 떨어지면 이벤트가 일찍 끝날 수 있다고 안내
- 스탬프: ⭐ 열심히 +1, 🙋 적극 참여 +1, 👑 MVP +2(수업마다 1명), 🔔 수업 준비 성공 시 반 전체 +1, ＋ 더 주기
- 빼기: 안 찍은 반죽 → 가장 최근에 찍은 **다 안 채운** 쿠폰 순서. 다 채운 쿠폰·교환권은 안전. 모자라면 마이너스
- **교실 패드에서 반 전체 주기·빼기 가능** (👥 반 전체 줄의 ＋ 전원 주기 / － 전원 빼기, 11/5 밤). 반 전체 빼기는 이유 "전체"로 남아요
- 되찾기 찬스: 빼기 **다음 날부터** 칭찬 1번에 1개(반죽으로). 반 전체 빼기에는 되찾기 없음
- 저금통: 200개 종례 스킵권, 400개 역사 시간 간식 파티. 기부하면 황금 붕어빵(+3) 확률이 올라요(학생에게 퍼센트 비공개)
- 친구 칭찬 15글자 이상, 반 친구 모두에게 한 번씩 보내면 처음부터. 가끔 행운 스탬프
- 학생은 처음 들어올 때 규칙을 끝까지 읽어야 시작
- **학생 코드는 숫자 4자리**(1000~9999). 담임이 6자리 추천을 듣고도 4자리를 골랐어요. 대신 한 기기에서 틀린 코드 5번이면 10분 막아요
- **학생은 처음 들어올 때 이름 + 코드**(11/5 밤). 서버(`me_`)가 모든 학생 요청에서 이름(띄어쓰기 무시)과 코드를 같이 봐요. 이름이 없으면 코드는 보지 않고 `LOGIN`만 돌려줘요(코드 맞히기에 쓰이지 않게). 학생 공용 주소 `?v=stu`
- 첫 화면·학생 로그인·패드 잠금 화면에 로고. 패드 잠금 화면엔 저금통 없음 (11/5 밤)
- **교실 패드는 소리 없음**. 노트북에서도 쓰니 PIN을 키보드로 칠 수 있어요(숫자·Enter·Backspace·Esc)
- 학생·담임 관리는 로그아웃 전까지 로그인 유지. 교실 패드는 잠김 유지(학생이 스스로 스탬프를 주지 못하게)
- 카카오톡 안 브라우저로 열리면 "🌐 브라우저로 열기" 안내가 떠요(`InApp`, `kakaotalk://web/openExternal?url=`). 구글 틀은 누를 때만 바깥 페이지를 움직일 수 있어서(sandbox에 `allow-top-navigation-by-user-activation`만 있음, 11/5 확인) **저절로 옮기기는 안 돼요**. "그냥 카카오톡에서 볼게요"는 그 탭에서만 기억해요
- QR 카드 A4 한 장에 16명(가로 4 × 세로 4), 카드에 코드 4자리 표시
- 교환권은 담임이 준 "쿠폰 출력기" 모양(크게 A4 6장 / 작게 A4 12장). "선생님 확인" 칸에 **보은쌤인 도장 그림**이 찍혀 나와요(11/12, `art/teacher-stamp.png`, 원본은 `bon17/coupon`의 `images/stamp.png`)
- **"재출력" 표시는 안 해요**(11/12). 이미 출력한 교환권도 골라서 몇 번이든 똑같이 다시 뽑아요(교환권 탭의 "고른 것 출력", 표 맨 위 칸으로 모두 고르기). 출력 횟수만 "출력" 칸에 남아요
- 미리캔버스는 안 써요. 포장마차 배경(천막·눈 덮인 산)은 앱이 그려요
- 굽기·찌기 그림은 5단계가 다 있을 때만 써요(일부만 있으면 앱 그림)

## 5. 함정 (실제로 겪은 것)

- **Apps Script는 HTML 파일의 `/* 주석 */`을 지워요.** 그래서 서버가 화면 정보를 넣는 자리는 글자 `'__BOOT__'`예요. 실행할 때 주석에 기대는 코드를 만들지 마요.
- **`ScriptApp.getService().getUrl()`은 doGet 안에서만 믿어요.** 시트 메뉴나 `google.script.run`에서는 편집용 배포 번호에 `/exec`를 붙인, 열리지 않는 주소를 줘요("현재 파일을 열 수 없습니다"). 그래서 doGet에서 본 주소를 스크립트 속성 `webAppUrl`에 저장하고(`liveUrl_`·`rememberUrl_`·`serviceUrl_`), 학생 링크·QR은 화면이 받은 `B.url`로 만들어요(`Adm.stuLink`).
- **담임이 GitHub 웹으로 올린 파일은 엉뚱한 곳에 갈 수 있어요.** 11/5에 그림 30장이 `art/`, 저장소 맨 위, **다른 브랜치**(`claude/loving-carson-2r4y16`)로 나뉘어 들어갔어요. 찾을 때는 저장소 전체와 모든 브랜치를 봐요:
  `git fetch origin '+refs/heads/*:refs/remotes/origin/*' && git log --all --author=bon17 --name-status`
- **CacheService는 6시간이면 사라져요.** 그래서 담임 로그인은 스크립트 속성 `adminTokens`(기기 10개까지)에도 적어요. 관리자 PIN을 바꾸면 다른 담임 기기는 로그아웃돼요.
- **Apps Script 응답은 1~3초 걸려요.** 학생 쿠폰 찍기는 누르면 바로 화면에 붙이고 저장은 뒤에서 묶어 보내요(`Stu.stamp`·`flushStamps`·`stampIdle`). 맛 고르기·기부·칭찬은 찍기 저장이 끝난 뒤에 해요. 교실 패드도 비슷하게 대기열로 보내요.
- **그림 data: 주소는 커요(장당 약 50KB).** 화면에 쓸 때는 `Art.url`로 blob: 주소로 한 번만 바꿔요(실제 Apps Script 화면에서 blob 그림이 뜨는 것 확인함).
- 학생 서버 동작(찍기·맛·기부·칭찬·규칙)은 시트를 다시 읽지 않고 `append_(rows, db)`로 응답해요. 응답이 다시 읽은 화면과 같은지 테스트가 확인해요.
- **인쇄 화면은 평소에 숨어 있어서 구글 글꼴 조각을 아직 안 받았을 수 있어요.** 주아·나눔고딕은 글자 묶음별로 나눠 받는데, 받기 전에 인쇄하면 '붕'·'빵'처럼 드문 글자만 다른 글꼴로 나와요(11/12 담임이 겪음). 그래서 `printHtml`이 `printReady`로 인쇄할 글자의 글꼴과 그림을 먼저 받고(최대 5초) 인쇄 창을 띄워요. 화면 테스트가 인쇄 창이 뜰 때 글꼴·도장이 받아졌는지 확인해요.
- 폰 화면: 천막은 고정하지 않아요(고정하면 내릴 때 제목과 겹쳐요). 글자는 `word-break:keep-all`.
- 휴대폰 맨 위 "Google Apps Script 사용자가 만들었습니다" 파란 줄은 구글이 넣는 거라 없앨 수 없어요.
